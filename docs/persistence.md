# Persistence, migration and replay

AgentIR persistence is split across two layers. `agentir-core` owns versioned snapshots, pure schema migration inputs and deterministic event replay but performs no I/O. `agentir-store` owns bounded file reads, version-specific archive codecs, the migration registry, integrity checks and atomic filesystem replacement.

## Archive identities and versions

The top-level envelope contains:

```text
format = "agentir.workspace"
format_version
compiler_version
snapshot
archive_hash = sha256(version-specific canonical archive body)
```

Archive format v1 and snapshot schema v1 are immutable legacy codecs published by commit `97c821a`. Archive format v2 and snapshot schema v2 add cached `spec_hash` and `semantic_canonical_version` to frozen revisions. New saves always write v2. The checked-in v1 fixtures are never generated by the current writer.

Archives larger than 64 MiB are rejected. Versions `0`, `3` and any other unknown value return `PERSISTENCE_FORMAT`; the reader does not apply serde defaults or approximate a future schema.

## Load pipeline

Before an archive becomes visible to the protocol engine, loading performs these steps in order:

1. read at most the configured byte limit;
2. inspect only the format/version discriminator needed to choose a codec;
3. deserialize the exact v1 or v2 envelope type;
4. recompute `archive_hash` with that source version's body rules;
5. apply the explicit migration registry (`workspace_archive_v1_to_v2`) or report the explicit v2 no-op;
6. require current snapshot schema v2;
7. replay every transaction and fork through the normal compiler core;
8. reproduce persistent IDs, parents, event hashes, revision `content_hash` and status summaries;
9. recompute and verify `spec_hash` plus semantic codec version for every frozen revision;
10. return the workspace only after all checks succeed.

Migration is a pure deterministic transformation over decoded archive/snapshot values. A v1 migration preserves every legacy `content_hash`, adds semantic metadata only to frozen revisions and leaves draft revisions without it. Original timestamps and continuation counter state are restored only after semantic replay succeeds.

## Save and migrate guarantees

`workspace.save` builds archive v2 in memory, writes a uniquely named same-directory temporary file, flushes and `sync_all`s it, then renames it over the requested path. A failed write removes its temporary file and leaves the prior destination untouched where the host filesystem provides atomic same-directory rename semantics.

`workspace.migrate_archive` first fully loads and verifies the source, migrates in memory, then atomically writes a v2 destination. The source is never edited. An existing destination requires `overwrite: true`; an identical source/destination path is therefore an explicit in-place replacement only when `overwrite` is true. Failed verification or migration creates no destination.

`MigrationReport` records source/target versions, applied step names, workspace/head/revision count, the verified old archive hash and the new archive hash when a destination was written.

This is atomic local replacement, not a concurrent database: there is no process lock, compare-and-swap generation or directory `fsync` in version 2.

## CLI lifecycle

Run one process to construct and save a workspace, then start a new process and call `workspace.load`. A successful load includes source `metadata`, a `migration` report and replay evidence. `workspace.verify_archive` performs the same validation without adding the workspace to the process.

The archive contains full graphs and event history, so it may include model-generated names, constants and provenance. Treat it as project data and apply normal filesystem access controls.
